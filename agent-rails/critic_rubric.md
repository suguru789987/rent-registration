# Critic ルーブリック（評価・棄却層 = ①却下）

- 由来: `JUDGMENT_LOG.md`（J-xxx / 逆算 R-xxx）と `verification/`
- 役割: エージェント出力を「現実基準」で採点し、AIがやりがちな誤りを **reject** する基準を宣言する
- ステータス: 検証雛形。要本人確認

## 使い方

エージェントが地代家賃に関する出力（計算・仕様提案・取込判定など）を返したら、
下記チェックを順に当て、1つでも fail なら **reject して理由を返す**。

## 棄却基準（fail = 出力を拒否）

### C-01 ｜ 算術を自前でやっていないか（演算分離）
- fail条件: エージェントが賃料額をLLM推論で「計算」している（`calc_rent` ツールを呼んでいない）
- 根拠: 決定論計算は必ずツールに委譲する

### C-02 ｜ 最低保証・条件選択を無視していないか
- fail条件: `rent_amount < min_guarantee`、または 合算/最大値選択 の分岐を取り違えている
- 根拠: `mock/spec.md §6`、`calc_rent.tool.yaml: invariants`

### C-03 ｜ 予算なし月へ適用していないか（③把握＋⑤先読み）
- fail条件: 予算未設定月にデフォルト計算額を適用する出力
- 根拠: rent R-002（予算期間機能なし）、`guardrails.yaml: no_apply_without_budget`

### C-04 ｜ 段階(tiers)を単月で変更していないか（④線引き）
- fail条件: 単月上書きで段階別歩合の段を編集する出力
- 根拠: `mock/spec.md §9`、`guardrails.yaml: no_tier_edit_in_monthly`

### C-05 ｜ 確認なしに上書きしていないか（⑤先読み）
- fail条件: 単月設定済み/確定値を、ユーザー確認なしに上書きする出力
- 根拠: rent R-005、`guardrails.yaml: no_silent_overwrite`（自動適用でなく二択提示）

### C-06 ｜ 無保証データを自動仕分けしていないか（ドメイン地雷）
- fail条件: 列名・形式が無保証の入力を、明示宣言なしに自動でマスタ生成・仕分けする出力
- 根拠: timerecord J-019（顧客データ無保証→自動仕分けは地雷）を地代家賃にも転用

### C-07 ｜ 「もっともらしい創作」をしていないか（②照合）
- fail条件: スキーマ/参照元に存在しない属性・費目・賃料体系を、もっともらしく生成している
- 根拠: AIのハルシネーション検出。`rent_schema.yaml` に無いものは fail

## 採点の出し方（推奨フォーマット）

```
verdict: pass | reject
failed_checks: [C-03, ...]
reason: 予算未設定の2026-01に賃料を適用しようとした（no_apply_without_budget違反）
```

## メタ原則（JUDGMENT_LOG の判断軸より）

- 判別不可ケースでUI/出力が破綻しない設計を優先（J-001）
- AIの「自分の構造に従いがち」傾向を疑う（J-001 振り返り）
- 技術的に可能でも運用上は地雷、を見抜く（J-019）
